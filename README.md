# Автотесты DemoQA Book Store

Финальное задание SimbirSoft по автоматизации тестирования. Python 3.12+, pytest, Playwright и requests.

## Запуск на Windows

Выполняйте команды в корне проекта. Для UI-тестов установите Google Chrome и Microsoft Edge. Версию Firefox, совместимую с Playwright, загружает команда ниже.

```powershell
py -3.12 -m venv .venv
$py = '.\.venv\Scripts\python.exe'
& $py -m pip install -e .
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $PWD '.playwright'
& $py -m playwright install firefox

& $py -m pytest -m "api or unit" -n 2 --dist loadfile --clean-alluredir --alluredir=allure-results/api --junitxml=test-results/api.xml
foreach ($browser in 'chrome', 'firefox', 'edge') {
    & $py -m pytest -m ui -n 2 --dist loadfile --clean-alluredir --browser-name=$browser --alluredir="allure-results/$browser" --junitxml="test-results/$browser.xml"
}
```

- `-m unit` запускает 29 автономных проверок схем и вспомогательных функций.
- `-m e2e` запускает три сквозных сценария, включая чистый API. `-m 'ui and e2e'` выбирает два сценария с браузером.
- `--headed` открывает окно браузера. Параметр `--browser-name` по умолчанию равен `chrome`.
- Для просмотра отчёта установите Allure CLI и Java, затем выполните, например, `allure serve allure-results/chrome`.
- Базовый адрес задаётся переменной `DEMOQA_BASE_URL` (по умолчанию `https://demoqa.com`). Таймауты задаются через `API_TIMEOUT` (секунды) и `UI_TIMEOUT_MS` (миллисекунды).

## Проверяемые сценарии

| Сценарий | API | UI |
|---|---|---|
| Список книг магазина | Статус, JSON Schema, уникальные ISBN, карточка книги и неизвестный ISBN | Сравнение списка с API, поиск по названию, пустая выдача и сброс фильтра |
| Список книг профиля | Пустая коллекция нового пользователя, JSON Schema, запрос без токена | Коллекция после добавления через API и после действий в браузере |

| Авторизация | Регистрация временного пользователя, авторизация, получение токена и неверный пароль | Успешный вход и отказ при неверном пароле |

В tests/unit/test_assertions.py находятся 29 автономных проверок.

| ID в Allure | Проверяемое поведение |

## Как устроен проект

- `framework/pages/` — Page Objects для входа, каталога и профиля.
- `framework/api.py`, `framework/schemas.py`, `framework/assertions.py` — клиент, JSON Schema и проверки ответов. HTTP 204 проверяется на отсутствие тела.
- `tests/` — сценарии pytest и фикстуры. Каждый тест с личной коллекцией использует отдельного временного пользователя. Очистка аккаунта выполняется и при сбое получения токена до запуска теста. Повторная подготовка коллекции вынесена в фикстуру seed_books, которая проверяет HTTP 201, структуру ответа, добавленные ISBN и сохранение книг в профиле. Браузер и каталог переиспользуются в рамках воркера, а контекст браузера создаётся на каждый тест.
- `allure-results/` — данные отчёта с названиями, шагами и скриншотами при ошибках браузерных тестов. `test-results/` — отчёты JUnit XML.
- `.github/workflows/tests.yml` — параллельный запуск через xdist и матрица Chrome, Firefox и Edge. CI формирует одностраничный HTML-отчёт Allure. Исходные результаты, HTML и JUnit сохраняются в артефактах.

Личные реквизиты для запуска не нужны. После теста временная учётная запись удаляется. В отчёты не выводятся токены и пароли, поле пароля на скриншоте маскируется.

## Контракт и известные отклонения

Вход с неверным паролем синхронизирован с POST /Account/v1/GenerateToken. После ответа проверяются HTTP 200, статус Failed и отсутствие токена, затем сообщение в интерфейсе ожидается в пределах UI_TIMEOUT_MS. Стандартный таймаут expect в 5 секунд заменён явным таймаутом приложения. Регрессионный UI-13 моделирует задержку сообщения в 6,5 секунды.

Схема полной записи книги требует все девять полей, перечисленных в BookModal. Проверяются типы, формат даты публикации и URL. Для страниц допускается числовой тип из Swagger, значение должно быть неотрицательным. Включены зависимости jsonschema для проверки форматов.

Swagger перечисляет поля BookModal без списка required. В тестах полного ответа закреплён весь набор полей, подтверждённый текущими ответами каталога, карточки и профиля. При регистрации используется фактическое имя userID. Коды ошибок проверяются как строки, что соответствует текущему API, при этом Swagger описывает code как число.

Функция expect_error требует явно передать ожидаемые code и message_contains. Код сравнивается точно. Ключевая фраза сравнивается без учёта регистра и повторных пробелов. Текст до и после ключевой фразы допускается. API-14 отдельно проверяет общий контракт ошибки валидации при исправлении известного HTTP 500, поскольку конкретные код и сообщение такого ответа пока не подтверждены.

Негативные проверки сверяют HTTP-статус, конкретный код и ключевую фразу сообщения для неверного пароля, неизвестного ISBN, дубликата, отсутствующей в коллекции книги и запроса без авторизации. Ответ с неправильным форматом массива ISBN отдельно проверяется на известный дефект DEMOQA-01.

[Swagger DemoQA](https://demoqa.com/swagger/) · [Book Store Swagger](https://bookstore.toolsqa.com/swagger/)

**DEMOQA-01.** В API-14 ожидается клиентская ошибка валидации 4xx. Перед запросом тест явно проверяет успешную авторизацию и доступ к пустому профилю. При повторной диагностике корректный запрос на добавление книги вернул HTTP 201, а строка вместо массива ISBN на том же аккаунте вызвала HTTP 500 с Content-Type text/html и сообщением collectionOfIsbns.map is not a function. API-14 прикладывает статус и формат ответа к Allure. Только для этой сигнатуры при сохранении пустой коллекции результат отмечается как `xfail`. Прочие неожиданные ответы считаются падением.

**DEMOQA-02.** После подтверждения «Delete All Books» сервер возвращает HTTP 204 и удаляет книги, но окно подтверждения остаётся открытым и профиль показывает прежний список. UI-06 проверяет сохранённое состояние после повторного открытия профиля. Отдельный UI-12 проверяет обновление текущей страницы без перезагрузки. Он получает xfail только при подтверждённом удалении на сервере, прежнем списке из двух книг и открытом окне подтверждения. К отчёту прикладывается скриншот. Иные ошибки считаются падением.
